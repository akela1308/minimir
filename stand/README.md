# Стенд 1.1: рассказ против механизма

Один агент, 200 шагов, четыре рукава на одном мире. Проверяется, идёт ли поведение
за действующим механизмом или за его описанием. Полное описание и критерии:
`PREREGISTRATION_STAND11_черновик.md`.

| файл | что делает |
|---|---|
| `env.py` | среда: записи, вопросы, показатель K, окно, действие B, внешние просадки |
| `prompts.py` | тексты для модели; рукава отличаются одним абзацем |
| `agents.py` | скриптовые боты и агент на языковой модели |
| `run.py` | прогон: семя = четыре парных эпизода |
| `analyze.py` | метрика, два контраста, вердикты |
| `calibrate.py` | проверка критериев на ботах, пишет `CALIBRATION.md` |
| `tests/` | 16 тестов |

Проверка без денег:

    python3 -m pytest -q tests
    python3 calibrate.py
    python3 run.py --agent experience --seeds 1001-1030 --out runs/bots.jsonl
    python3 analyze.py runs/bots.jsonl

Прогон на модели (ключ задаётся в окружении и в файлы не попадает):

    export STAND_API_BASE=https://api.deepseek.com
    export STAND_API_KEY=...
    export STAND_MODEL=точный-идентификатор-модели
    python3 run.py --agent llm --seeds 2001-2005 --out runs/pilot.jsonl
    python3 analyze.py runs/pilot.jsonl

Все промпты и ответы пишутся в `runs/<имя>_calls/` по файлу на эпизод. Прерванный
прогон продолжается той же командой: готовые семена не пересчитываются.

Через GitHub без своей машины: Actions, workflow «стенд 1.1», кнопка Run workflow.
Ключ лежит в секрете репозитория `STAND_API_KEY` (Settings, Secrets and variables,
Actions). Режим `pilot` считает семена 2001-2005; режим `confirm` считает только
после заморозки предрегистрации. Результаты коммитятся в `stand/runs/`.

Семена: 1001-1999 боты, 2001-2099 пилот, 3001 и дальше подтверждающий прогон,
50000 и дальше калибровка.
